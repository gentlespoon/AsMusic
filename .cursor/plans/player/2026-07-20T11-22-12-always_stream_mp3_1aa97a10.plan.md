# Always request MP3 from Navidrome

## Decision

Every stream and offline download uses Subsonic `format=mp3`. No `maxBitRate` (Navidrome uses its configured transcoder default; already-MP3 sources stay raw). Offline blobs use `OfflineMediaKey.variant = 'mp3'` so we never play pre-existing raw WMA/etc. caches.

```mermaid
flowchart LR
  play[Player / Download]
  url["getStreamUrl + format=mp3"]
  nd[Navidrome]
  cache[Server transcode cache]
  offline["OfflineMedia variant=mp3"]
  play --> url --> nd
  nd -->|miss| cache
  nd --> play
  url --> offline
```

## Changes

### 1. Shared stream constants

In [`packages/core/src/offline/OfflineMediaStore.ts`](packages/core/src/offline/OfflineMediaStore.ts) (or a small sibling under `packages/core/src/offline/`), export:

- `STREAM_FORMAT = 'mp3'`
- `OFFLINE_MEDIA_STREAM_VARIANT = 'mp3'` (same string; used as `OfflineMediaKey.variant`)

Re-export from `@asmusic/core`.

### 2. Always add `format=mp3` to stream URLs

In [`packages/ui/src/contexts/ServerAndLibraryContext.tsx`](packages/ui/src/contexts/ServerAndLibraryContext.tsx), extend `getStreamUrl` params:

```ts
params.set("format", STREAM_FORMAT); // 'mp3'
```

Call signature stays `(serverId, trackId)` — no suffix plumbing. Playback, persist-while-streaming, and bulk download already share this builder.

### 3. Offline keys use the mp3 variant

Pass `variant: OFFLINE_MEDIA_STREAM_VARIANT` everywhere we read/write offline audio for streaming:

| Site                                                | File                                                                                                                                                      |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Playback resolve                                    | [`packages/core/src/offline/playbackResolver.ts`](packages/core/src/offline/playbackResolver.ts) — include variant in `getReadyPlaybackSource`            |
| Persist while streaming                             | [`packages/ui/src/player/core/PlayerManager.ts`](packages/ui/src/player/core/PlayerManager.ts) `startPersistWhileStreamingIfNeeded`                       |
| Bulk / single download enqueue                      | [`packages/ui/src/contexts/OfflineDownloadContext.tsx`](packages/ui/src/contexts/OfflineDownloadContext.tsx) — set `key.variant` on `OfflineBulkJobTrack` |
| Download status / remove                            | [`packages/ui/src/shared/songItem/useSongItemOfflineActions.ts`](packages/ui/src/shared/songItem/useSongItemOfflineActions.ts)                            |
| Any other `getStatus` / `delete` for stream offline | grep `trackId` + `offlineMedia` in UI                                                                                                                     |

Downloaded list UIs already surface `key.variant`; no special UI needed. Pre-existing rows with empty variant remain on disk but are unused for play/status (appear as not downloaded until re-fetched). No automated purge in this change.

### 4. Out of scope

- Player settings / bitrate picker
- Platform-specific format allowlists
- iOS MIME/extension changes (transcoded body is MP3; existing `audio/mpeg` defaults are fine)
- Server admin docs beyond noting ffmpeg/transcoding must be available on Navidrome

## Verify

- Play a WMA track on iOS: stream URL includes `format=mp3`; audio plays.
- Play an existing MP3: still works (Navidrome returns raw).
- Offline download the WMA track, then airplane-mode play: uses `variant=mp3` local file.
- Confirm an old empty-variant offline row is ignored for “downloaded” indicator and playback.
